Student: Taylor Sanders
Date: October 22, 2026
Target review date: October 30, 2026

## Primary competency

My primary competency is application state, navigation, and interaction. I
will continue my Packaging Design Gallery and practice every slice listed for
this contract:

- Identify information the interface needs to remember during a session.
- Manage state so changes are reflected consistently in the interface.
- Save and retrieve appropriate data with `localStorage` when persistence is
  useful.
- Validate stored data and handle missing, malformed, or outdated values.
- Create links that carry an identifier or other context in the URL.
- Read and validate search parameters with browser APIs.
- Fetch or select detail data based on a URL parameter.
- Handle missing, invalid, or unknown parameters with a useful user
  experience.
- Model open and closed states clearly in JavaScript and CSS.
- Keep visual state, keyboard behavior, and ARIA state synchronized.
- Support Escape, focus movement, click-away behavior, or other appropriate
  interaction details.
- Reuse interaction logic across pages or components.

I will connect these slices through a gallery flow: visitors can open a
packaging item's detail page using its URL identifier, save favorite items
across visits, and use an accessible view-more interaction that does not push
the other cards down. I am not claiming that this contract completes the
whole competency.

## My learning plan

I will keep working on the Packaging Design Gallery so I can build on the
cards and data I already have.

I will use these resources:

- The course learning module on URL parameters
- My class notes on JavaScript events, state, and DOM updates
- Browser developer tools to inspect URLs, storage, console output, and
  network/image loading
- The browser documentation for `URLSearchParams` and `localStorage`

I will practice in this order:

1. Decide what information the gallery needs to remember during a visit and
   what should persist between visits. I will use favorite item IDs as the
   persisted state if that fits the existing gallery.
2. Add links from gallery cards that include an item identifier in the URL.
   Read the identifier with `URLSearchParams`, validate it, and select the
   matching item for the detail view.
3. Show a useful message when the URL has no identifier or an invalid or
   unknown one, rather than leaving a broken or empty detail page.
4. Save and retrieve favorite item IDs with `localStorage`. Check the stored
   value before using it, including when it is missing, malformed, or refers
   to an item that is no longer available.
5. Replace the card's expanding view-more content with an interaction that
   shows details without pushing the other cards down. Keep its open and
   closed state in sync with its appearance, keyboard behavior, and ARIA
   attributes; support Escape and sensible focus behavior.
6. Reuse the interaction behavior for the gallery cards instead of writing
   separate logic for each one.
7. Test the flow with valid, missing, and unknown URL identifiers; test saved
   and invalid storage values; and try the interaction with only a keyboard.
8. After the main flow works, use the network panel and focused console
   measurements to investigate slow image loading and improve or explain one
   bottleneck.
9. Check how the Brandfetch client ID is used. I will not put a credential
   that must remain secret in browser JavaScript or assume that moving it to
   another frontend file makes it private. I will follow the API's
   requirements, use only an explicitly public client identifier in the
   browser, or use a server-side approach if a secret is required.

My first milestone, due October 26, is a working gallery link that opens the
correct detail view from its URL identifier and gives a clear message for an
unknown identifier.
